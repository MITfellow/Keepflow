Security Architecture

Last updated: November 9, 2026 · Product design overview

Security and privacy are central to Keepflow’s product design. This page describes the security principles and planned architecture shown in the Keepflow experience. It is not a certification, audit report, or guarantee that every control is implemented in every environment.

Core principles

  • User control: Sensitive actions (such as sending messages or placing orders) are designed to require clear approval before execution.
  • Least privilege: Integrations and tools should receive only the access needed for the task the user authorizes.
  • Isolation: Agent work is designed to run in isolated compute environments to reduce blast radius and protect user data.
  • Transparency: Users should be able to review what the agent did, what it plans to do, and which permissions are active.

Planned and illustrative controls

  • Secure execution environment: A dedicated, isolated environment (conceptually a per-user or tightly controlled cloud workspace) for browser and task execution.
  • Credential handling: Credential storage and injection patterns intended to avoid exposing raw secrets to the model or unnecessary systems; third-party password manager integrations where supported.
  • Payment safety: Use of virtual or tokenized payment methods where available, with user approval before checkout actions.
  • Auditability: Activity records for important actions, approvals, and outcomes.
  • Transport and platform security: HTTPS/TLS in production deployments, secure hosting configuration, and dependency management appropriate to the stack.
